Checklist de validación para mi-horario

Basado en las 6 mejores prácticas que cruzan todas las fuentes investigadas:

✓
1. Información jerárquica (broad → specific)

Calendario mensual como navegación broad → click día → drawer con detalle specific.
✅ Nuestra opción A/C cumple exactamente

✓
2. Acciones visibles y contextuales

"+ Bloquear" y "Editar horario" en el drawer del día, no escondidos en menús o tabs separados.
✅ Soluciona el SheetTrigger roto actual

✓
3. Drawer responsive: lateral en desktop, bottom sheet en mobile

Desktop: drawer lateral derecho con scrim, focus trap, Escape cierra, close button visible.
Mobile: bottom sheet con grab handle, detents (peek → half → expanded), swipe dismiss + close button.
✅ Patrón estándar de la industria

✓
4. Estados de datos completos

🟡 Loading: skeleton del calendario, no blank screen
🔴 Empty: "Selecciona un día para ver detalle" en drawer
🔴 Error: mensaje + retry dentro del drawer, no se cierra
✅ Diseñar data lifecycle upfront

✓
5. Colores + iconos (nunca color solo)

Estados de día: 🔴 Cerrado / 🟡 Parcial / ✅ Abierto — usamos color + símbolo + texto.
WCAG 2.2 SC 1.4.1: no usar color como único medio de información.
✅ Ya lo tenemos diseñado así

✓
6. Responsive sin overflow horizontal

WCAG 2.2 SC 1.4.10 (Reflow): calendario debe reflow sin overflow a 320px.
En mobile: grid se achica, días siguen siendo tappables (mín 24×24px, ideal 44×48px).
✅ Usar grid-cols-7 con min-width 0, overflow-hidden

Lo que viene de la industria que refuerza nuestro diseño

UX Patterns — Calendar View

"Use calendar view when users compare activity across many days. Use for operational scheduling and booking."

"Keep filters, summaries, and data visibly connected. Preserve scannability as the viewport shrinks."

NNGroup — Bottom Sheets

"Bottom sheets preserve substantial visibility of the underlying information — useful when users need to refer to main content while interacting with the sheet."

Include visible Close button. Don't rely on gesture alone.

Eleken — Calendar Design

"Show event details in side panels instead of disruptive modal windows."

"Make 'add event' obvious and one-tap accessible."

"Don't hide key actions behind tiny buttons or deep menus."

MyShyft — Scheduling UX

"Clear organization from broad (monthly view) to specific (individual shift details)."

"Consistent access to core functions regardless of where users are."

Veredicto: Opción A (o C)

Basado en todo el research de industria, referencias reales, y buenas prácticas de UX:

Opción A — Calendario mensual + drawer lateral (desktop) / bottom sheet (mobile) + selector de profesional. Es la que más se alinea con DaySpark, Nabú, Zenoti, GlossGenius y las mejores prácticas de calendar scheduling UX.

Opción C — Solo calendario mensual (aún más minimalista). También válida, especialmente si el selector de profesional se mueve a un filtro arriba.
