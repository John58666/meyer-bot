Resumen: mejores prácticas aplicadas

1. Drawer lateral (desktop)

  • Scrim semitransparente sobre el calendario
  • Focus trap + Escape cierra + Tab cíclico
  • Close button visible (✕) — no solo gesture
  • Ancho fijo 340px, no cambia con scroll
  • Al cerrar: focus vuelve al día seleccionado

2. Bottom sheet (mobile)

  • Grab handle + 3 detents: peek (25%) / half (50%) / full (95%)
  • Swipe down + close button para cerrar
  • No stacking: solo un sheet abierto a la vez
  • Keyboard ajusta posición del sheet
  • Touch targets ≥ 44px (WCAG 2.2 SC 2.5.8)

3. Calendario responsive

  • grid-cols-7 con min-width:0 — sin overflow horizontal
  • 320px: textos más chicos pero legibles, sin scroll
  • Días con indicador de estado: color + icono + texto
  • Leyenda siempre visible debajo del calendario

4. Estados de datos

  • Loading: skeleton en drawer, calendario intacto
  • Empty: "Selecciona un día para ver detalle"
  • Error: mensaje + botón "Reintentar" dentro del drawer
  • Nunca se cierra el drawer en error — el usuario no pierde contexto

5. Accesibilidad

  • Keyboard nav: flechas en calendario, Tab en drawer
  • ARIA: role="dialog" + aria-modal="true" en drawer modal
  • Screen reader: cada día lee "Viernes 7 Febrero 2026"
  • Color no es única fuente: ● + texto + icono
  • Dark mode nativo con shadcn

¿Qué pasa con...

PreguntaRespuesta
¿Dónde va "Horario recurrente"? Sigue siendo un modal aparte. El drawer del día puede tener un link "Usar horario recurrente" que abre el modal actual.
¿Y si el profesional no tiene horario ese día? El día se muestra sin color (— Sin configurar). El drawer muestra "Este día no tiene horario. ¿Quieres configurarlo?" con botón "Crear horario".
¿Cuándo se cierra el drawer? Al hacer clic fuera (scrim), presionar Escape, clic en ✕, o seleccionar otro día (se actualiza el contenido).
¿Multi-profesional? El dropdown de profesional permite cambiar. Al seleccionar otro, el calendario se recarga con los datos de ese profesional.
